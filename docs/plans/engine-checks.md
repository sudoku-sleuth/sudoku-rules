# Open Rules engine: checks and acceptance details

Companion to [the owner plan](engine.md). Proposed requirements, not implemented checks.

## Complete check-by-fixture inventory

Invalid documents must be writable: store raw Markdown under `tests/invalid/{cases,rules}/`, outside publishable content. The editor retains and saves source with diagnostics even when parsing fails; a typed serializer must not be the only way to create a test input. Lint rejects these files with a nonzero exit and never silently repairs, skips or coerces them.

The following inventory specifies each planned check and its deliberately invalid fixture. Names are relative to those two corpus directories; `@line:column` is the exact, one-based primary error location the fixture must be authored to produce. `tests/invalid/expected.json` records each file's full ordered diagnostic list: stable code, spec check ID, exact setter-facing message, optional technical detail, file and start/end span. Resolver fixtures also record exact requested URLs and injected responses, redirects or failures; diagnostics attach to the originating reference and include dependency-source spans. CI asserts exact equality, including absence of extra diagnostics, rather than matching an error substring. Checks become mandatory with their owning slice; example verdict checks start in slice 4.

The manifest expands grouped rows into individual fixtures and includes each concrete spec-declared refinement, not just one example per generic error code. Every checker rule has a rejecting fixture and a repaired accepting counterpart; there must be at least as many rejecting scenarios as accepting scenarios. Add deterministic, single-fault mutations across the 3,887 valid cases to meet that balance. CI runs both corpora and fails if a new check lacks an invalid fixture, a registered check never fires, a previously rejected file passes, or its exact diagnostic changes without an approved expectation update. Include a second library root, a full-URL setter rule and changed trust configurations in accepting/invalid pairs; no fixture requires one hard-coded host to pass. This coverage gate ships with slices 1–3 and expands with later slices; rejection runs count inside the existing phase budgets.

## Detailed slice contracts

The following preserves the APIs, file layout, migration evidence, tests and risks behind the short plan. Goal 1 comes first; goal 2 is later.

Read the seven source shape pages, their contract README, and the generated library. The main source checkout lacks `predicates.md` and `logic.md`; the current versions are in the `open-rules` worktree. They classify 77 kinds: 45 first-order, 28 with aggregates, four existential. Public parameter metadata currently has descriptions and prose defaults, rather than executable types. Formulas still contain prose bindings, implicit domains, and indexed predicate notation. The public repo's specification-lint hook currently checks nothing.

Move the normative definitions here before replacing that hook. A rule's meaning lives in its library spec page and formula. A case references definitions by URL and supplies parameters; it does not supply or regenerate their logic. Resolve a short kind against the case's `library:` root to `<kind>.md`; a full URL selects that page directly, including on another host. No URL or trusted host is hard-coded in the engine or CLI. `https://rules.sudoku-sleuth.com/` is simply the root our own case files declare. The host supplies `trustedLibraries`; Sudoku Sleuth configures its own library in deployment configuration. Parameters, applicability, geometry, defaults, and auxiliary-answer requirements must be declared in the spec. Generic language primitives implement arithmetic, sets, and board operations; no kind-specific validation branches, unknown-term whitelist, or inference from English. Published meanings remain immutable; a changed hash at the same URL is an error, and changed meanings require new kinds.

An embedded custom definition is the explicit exception: compile it through the same parser, name resolution and type checks, mark it `custom` and unverified in the typed case/report, and treat it as a candidate for promotion to the library. It cannot override a fetched definition for its URL or redefine/shadow a library kind, alias or shared term. Fetched definitions outside configured trusted libraries are also unverified, even if they use familiar names. Promotion creates a reviewed library definition; it never happens implicitly during lint or solving.

Layout: `spec/{grammar.ebnf,types.md,logic.md}`, typed declarations and formulas in `rules/predicates.md` and `rules/<kind>.md`; `src/{language,library,case,resolve,model,evaluate,generate,propagate,proof}`, `src/cli.ts`, `tests/{language,cases,resolve,examples,conformance,proof}`, and `bench/corpus.json`. Only the CLI reads files. Pure parsing never fetches; resolution uses an injected fetch in Node, Workers or the browser. Definitions remain data, never executed source code.

## Goal 1: specification, linter and tools

### 1. Formula language — Friday launch requirement

**Scope/API.** `parseFormula(text) → AST`, `compileLibrary(pages, prelude) → TypedLibrary | Diagnostics`. Write the complete EBNF and precedence rules: quantifiers and binders; Boolean connectives; comparison, membership and subset relations; arithmetic, powers and exact division; absolute value/cardinality; finite Σ, Π and count; set comprehension, intervals, indexing, predicate calls, local `where`/conditional bindings, and typed predicate lambdas. Normalise Unicode spellings without losing source spans. Parse the prelude through the same pipeline, including indexed families and finite schemas.

Each term declares argument/result types: cell, digit/value, position, number, path, cell set, Boolean, plus enums, records, optional values and collections/functions needed by existing formulas. Declare board inputs explicitly; distinguish positions from cells and digits from transformed values. Resolve every name to a binder, parameter, declared context input, or defined term, with matching arity/types. Guard optional/indexed operations, reject unchecked recursion, and derive the logical class from the typed AST.

**Ships/tests/budget.** `src/language/` plus prelude migration; parse/type-check every page. Test unknown `partial`, wrong arity/type, unbound indices, shadowing, overloaded `|·|`, scoped lambdas and malformed notation against exact diagnostics in the invalid corpus below. **≤10 s** cold library compilation. Risk: formalising prose such as `magicLines` and `BoardDiagonals` needs explicit definitions, not parser exceptions.

### 2. Rule lines — Friday launch requirement

**Scope/API.** `parseCaseEnvelope(text) → UnresolvedCase | Diagnostics`, then `parseCase(envelope, resolvedDefinitions) → TypedCase | Diagnostics`. First collect the root, references and raw argument tokens without assuming a built-in kind registry. After slice 3 resolves the pages, derive each kind's line grammar and parameter validation from their front matter declarations: types, required/optional status, typed defaults, enums, aliases, positional roles, occurrence policy and cross-field predicates. No per-kind linter code. Evaluate parameter-only refinement ASTs here; grid/answer evaluation follows in slice 4. Preserve rXcY coordinates, ordered occurrences and setter prose. Treat standard-board expansion and aliases as declarations too.

Generic cell validation checks board membership. Separate unrestricted ordered cell sequences from paths refined by a declared adjacency relation; the current prelude does **not** require every authored line to move orthogonally. Connectedness and loop closure apply only where the declared type requires them. Single occurrences use implicit kind IDs; repeating kinds use unique numbered IDs, avoiding board-house IDs. Validate unknown kinds, duplicate/extra parameters, conditional requirements, missing defaults on nonstandard boards, and custom definitions through the same typed formula pipeline. Reject `flags` on a `read` or `confirmed` case; a `flagged` case must supply reasons. Successful custom parsing still reports its custom status; it does not confer library membership.

**Ships/tests/budget.** `src/library/`, `src/case/`, CLI and browser exports; replace this repo's hook and the skill's published-command slot with `openrules lint`. Regression-test kind misuse, off-board cells, broken refined paths, repeats/IDs, aliases and all **3,887 frozen cases**, including equivalent cases with a different `library:` root. **≤20 s** case parsing/validation. Risk: metadata migration must preserve approved omission behaviour rather than infer it from parameter names.

### 3. URL resolver and compiled model — Friday linter requirement

**Scope/API.** `resolveCase(envelope, {fetch, cache, previousLock, trustedLibraries, limits, signal}) → ResolvedDefinitions | Diagnostics`; `compileCase(text, options) → CompiledPuzzle | Diagnostics` orchestrates envelope parsing, resolution, definition parsing/checking and typed instantiation. Resolve every referenced page, plus its explicitly declared prelude/import dependencies. Parse and check every fetched definition through slice 1, then validate arguments through slice 2. Ordinary prose links are not imports. Embedded custom definitions provide explicitly recorded local sources; a same-URL collision with fetched content is rejected.

Use a URL index and a content-addressed cache keyed by SHA-256 of the exact page bytes. Deduplicate requests across cases, permit conditional revalidation, and record a deterministic lock in the compiled output: requested/effective URLs, redirects, page hashes, dependency edges, embedded-definition hashes and language/compiler version. Persist the host trust-policy digest separately from content identity. Compare fetched/revalidated bytes against `previousLock` and the stored URL/hash association; any changed hash for the same URL raises `E_RULE_CHANGED`, never silently updates the lock. A first encounter establishes a hash; detecting later changes requires retaining that history. A new meaning gets a new kind/URL.

Trust comes only from host-configured library roots, using normalised URL/path boundaries and the actual resolved URLs. A redirect or unverified dependency cannot inherit trust from its requested URL. Every external page passes the same grammar/name/type/refinement/example checks. Mark its constraints unverified and, in goal 2, allow only generated checkers/propagation; never dispatch hand-written techniques to it or let those techniques use it as a premise. Configure server fetch policy separately from semantic trust: explicit schemes, redirect/network policy, byte/page/depth limits, deadline and cancellation. Reject unreachable pages, non-rule documents, dependency cycles, excessive size and timeouts; never continue with missing constraints.

**Where/API boundary.** Compile once at import/settle and atomically persist `CompiledPuzzle`: versioned serialisable board and auxiliary schema, typed definition ASTs, parameter bindings, stable instance IDs, dependency scopes, trust provenance and the lock. Invalid resolution cannot replace a valid stored model. Never resolve on a page request; goal 2's solver and Desk consume this contract through adapters, not fetched Markdown or a private duplicate spec. The editor resolves live in a worker while the setter edits, cancelling stale requests and reusing checked hashes.

**Ships/tests/budget.** `src/resolve/`, `src/model/`, CLI options `--trusted-library <root>` (repeatable), `--lock <file>` and `--offline`; no implicit trusted root. Default lint resolves declared URLs; CI injects frozen responses and asserts the same locks without network. Test alternate roots, full external URLs, zero/two trusted roots, redirect/dependency trust, cache/revalidation, hash changes and every resolver failure below. **≤5 s** frozen resolution/cache work; live resolution defaults to a 10 s total deadline and configurable resource caps. Risk: external availability/CORS and immutable-URL violations must remain explicit errors.

**CORS verification, 12 October:** the live `thermo.md` header probe failed DNS resolution, and the independent web fetch was inaccessible; CORS is not verified. Before browser-editor release, require a successful cross-origin GET from the editor origin to the deployed raw Markdown and prelude, including redirects, with readable bytes and `Access-Control-Allow-Origin: *` or the editor origin. Test failures as `E_FETCH_CORS`; use credential-free fetches. GitHub Pages deployment is the intended host, not evidence that this endpoint's headers are correct. Other hosts must allow CORS too, or the host must explicitly provide an approved fetching adapter.

### 4. Evaluator and worked examples — Friday target; complete goal 1 just after if needed

**Scope/API.** `evaluate(ast, grid, auxiliary, budget) → {verdict, trace}` and `checkExamples(library) → Report`. Verdicts are true, false, unknown, or invalid input. Partial grids carry explicit known digits and candidate domains; missing required witnesses are incomplete, never guessed. True must hold for every remaining completion, false must have no satisfying completion; otherwise return unknown. Resource exhaustion also returns unknown. Auxiliary answers are typed and shared across rules: modifier membership, electrons, regions, hidden cages and expression letters.

Represent examples as rule instances, assignments, auxiliary inputs and expected outcomes. Require Satisfies=true and Breaks=false, with all dependencies supplied. Fragment examples check the named rule, not unrelated unfinished Sudoku houses. Generate numeric explanations from the trace; normative example text cannot independently assert arithmetic or outcomes. Keep setter-authored puzzle wording separately. This prevents values and explanation text from disagreeing.

**Ships/tests/budget.** `src/evaluate/`, structured examples and rendered readings; test every example, mutate values/expected results, test partial-grid verdicts, shared witnesses and exact negative/integer arithmetic. **≤10 s** for library examples. Risk: broad integer quantification, products and powers need explicit domains or sound bounded reasoning; incomplete reasoning never certifies an example.

## Goal 2: our engine and product integration — later

### 5. TypeScript checkers and model consumers — later

**Scope/API.** `generate(checkedDefinitions) → TypeScript modules`; generated `checkCase(compiledPuzzle, grid, auxiliary, budget)` retains evaluator verdicts and traces. Lower the resolved, checked definition ASTs to deterministic modules and a small portable runtime with no Node/DOM dependencies, dynamic eval, or source execution. Add solver and Desk adapters for `CompiledPuzzle`; export identical modules for those consumers and the editor, bound to the lock's page hashes. Restore persisted models without network resolution and reject unsupported model versions explicitly.

Generation requires a compiled library, with a separate compiled custom namespace where present. Cases instantiate those definitions; no solver component is generated solely from a case file. Watson's techniques remain hand-written human logic. Generated checkers and basic propagation provide constraints and evidence against which those techniques are proved, not generated replacements for the techniques.

**Ships/tests/budget.** `src/generate/`; reproducible output, browser import tests, interpreter/generated parity, exhaustive small grids and differential tests against each hand-written solver checker. Existing `logic.md` records disagreements, including constructed-region joins/borders, remainder normalisation, modifier eligibility, signed parity and hidden-modular extents. Preserve counterexamples and adjudicate against the spec; do not alter formulas merely to obtain agreement. **≤5 s** generation/smoke comparison in CI; larger differential runs are separate. Risk: numeric representation and optimiser rewrites must preserve exact semantics.

### 6. Propagation and proof — later, after checker conformance

**Scope/API.** `propagate(instance, domains, auxiliary, budget) → {removals, proofs, status}`; `verifyTechnique(premises, deduction, case) → proof | counterexample | unknown`. Generate rule-local candidate support checks: remove a candidate only when every permitted assignment in that rule's dependency scope fails. Keep auxiliary choices jointly consistent; global rules have global scope, not an invented local shortcut. A budget stops work without removing unsupported candidates.

**Ships/tests/budget.** `src/propagate/` and `src/proof/`; replayable AST/instance/premise evidence feeds the shared deduction ledger and hints. Exhaust cheap propagation to a fixed point before speculative work. For each solver technique, prove premises plus the full generated constraints entail the deduction: search for a valid completion violating it. A model is a counterexample; exhaustive unsatisfiability is a proof; timeout is unknown. Exhaustive finite-domain small-board tests, monotonicity, order-independent closure, proof replay and corpus regressions supplement this harness; random agreement alone is not proof of universal soundness. **≤8 s** bounded CI smoke tests; full technique/domain certification runs separately. Risk: exponential support search limits strength and proof coverage, never correctness.

## Measurement and release gates

Freeze the complete library, 3,887-case corpus and resolved page/lock fixtures with content fingerprints. Measure cold elapsed wall time on the CI runner, including reads, diagnostics and rejection fixtures, with injected fetch responses and no network. Resolve/compile each distinct definition once. Record phase times, peak memory and worst cases. The 58 s budget covers lint and bounded checks, not solving 3,887 puzzles or unbounded proof searches. Browser edits target 100 ms with checked definitions cached; network loading is separate. Missing declarations, resolver failures and known semantic disagreements block the affected release gate; none receives a silent exception.
