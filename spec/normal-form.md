# Semantic normal form

The portable API compares rule meanings on a supplied board. It reads complete Markdown rule files, preserves source spans and reports coverage for each declaration. It performs no I/O. All fixtures use independently written synthetic rules.

```ts
import { normalise, compare, type BoardContext } from "@sudoku-sleuth/open-rules";

const board: BoardContext = {
  rows: 4,
  cols: 4,
  alphabet: [0, 1, 2, 3],
  activeCells: Array.from({ length: 16 }, (_, i) =>
    `r${Math.floor(i / 4) + 1}c${i % 4 + 1}` as const),
  houses: [{ cells: ["r1c1", "r1c2", "r1c3", "r1c4"] }],
};
// Each input is {file: string, text: string}, including its Open Rules header
// and fenced rules block. File names locate diagnostics; they do not affect meaning.
const a = normalise(leftFile, board);
const b = normalise(rightFile, board);
const result = compare(a, b);
```

`normalise(file, board)` returns `status: complete | partial | invalid`, `issues`, and a `normalForm` for complete or partial inputs. Invalid inputs have no usable form. A form contains `version: 1`, canonical board context, `solution`, `play`, per-instance `coverage`, `sources` and `rewrites`. Source identities and rewrite records are separate from canonical mathematical identity. Call the normaliser again on the same inputs to reproduce the form; its tree rewrites are idempotent.

`compare(a, b)` takes two normalisation results. It returns:

| Field | Meaning |
| --- | --- |
| status | `equivalent` for equal complete forms on the same board with equal, covered play semantics; `unresolved` for structural differences or any uncovered meaning; `invalid` for a rejected input. |
| covered | `equal`, `structural-difference` or `invalid`, independently of whole-file status. |
| differences | Unmatched primitives with cells, side, complete term, source spans and a message. Board differences name changed fields. |
| uncovered | Unsupported declarations from each side, each with its own specific reason and source. |
| issues | Located input errors. |

Unequal forms establish a structural difference. They do not prove different sets of full-board solutions. This API does not search for witnesses or evaluate arbitrary answers. No `different` verdict is emitted without that later proof step. Equal partial forms stay unresolved, including two identical unsupported declarations. Metadata such as title, setter, source, status, prose and drawings belongs to a separate envelope comparison. It is excluded from mathematical identity. Declaration `meta.stated`, `meta.name` and
`meta.strips` are retained by the declaration reader but excluded from solution
and play identity. They leave fog setup and visibility unchanged. Fog setup has a separate canonical play identity. Whole-file agreement requires both solution and play identities to agree.

The package's existing `compare(Rational, Rational)` overload continues to return -1, 0 or 1.

## Board context

Coordinates are one-based `r1c1` strings. The ordered alphabet contains distinct whole-number face digits, including zero or negative digits. Values are numeric digits, never candidate indices. Active cells are supplied explicitly; canvas dimensions introduce no cells or houses. An inactive cell cannot occur in a declaration, given, region or house.

`regions` is an optional primary partition of the active cells. It describes geometry. Only `houses` asserts unconditional pairwise digit inequality. Each house can carry `source: Span` and `id`; those survive as provenance. Short houses assert distinctness without adding missing-digit coverage. `givens` supplies `{cell, digit}` records. Ordered alphabets, coordinates, active cells, primary regions, houses and givens all enter board identity. House IDs, source locations, region order, cell-set order and given-record field order do not.

Supply one board and one alphabet. Multiple-board input or unknown BoardContext fields is rejected. A header containing unhandled board fields is reported as uncovered. Several overlapping boards with local alphabets are outside this representation.

Headers fall into two classes. The case's text headers `title`, `setter`, `source`, `case`, `status` and `flags` never change what a solution is: they lower as covered with no formula and do not mark the effective-value domain unresolved. `format`, `library` and `negate` are read directly. Every other header is reported uncovered ("The <name> header's semantic meaning is not lowered") and, as before, marks the effective-value domain unresolved, so value-reading rules in the same file stay uncovered. A header joins the text class only when this spec states that it has no effect on solutions; `src/semantics/headers.ts` holds the one list.

A caller can pass `metadataHeaders`, a list of header names it declares carry no meaning for solutions, to `normalise(file, board, options)` and `canonicalise(page, board, templates, options)`. Listed headers are treated as the text headers are: covered with no formula, never marking the value domain unresolved. Without the declaration an unknown header stays uncovered, and the caller answers for the declaration. Naming a header the spec defines with meaning (`board`, `givens`, `regions`, `fog`, `negate`, `library`, `format`) is an error: `normalise` returns `invalid` with `E_SEMANTIC_HEADER` and `canonicalise` throws. A `canonicalise` proof normalises with every header of the file, so an undeclared unknown header leaves the rewrite unproven and it is reported as kept.

Recognised header board fields (`rows`, `cols`, `symbols`, `activeCells`, `regions`, `houses`, `givens`) must agree with BoardContext. Header givens accept cell/digit records, a digit grid using dots for empty cells, or `r1c1=1` entries. Top-level extra `regions` must appear among the supplied houses. A `board.regions` partition alone asserts no uniqueness. The supplied context is resolved data; this API does not guess missing alphabets or region layouts.

The published `sudoku 9x9` declaration supplies the standard 27 houses, standard box geometry and digits 1–9. It requires the matching complete board and ordered alphabet; any supplied primary regions must match the nine standard boxes. Its houses become unconditional assumptions only for a positive declaration. `not sudoku 9x9` negates the whole house composition once; geometry and givens remain board data. For 4×4, 6×6, 0–8, irregular or inactive-cell boards, supply explicit context and declare the required houses there or with `unique`.

## Primitives and exact meaning

Version 1 implements the following finite fragment of the logical tree. All nodes denote Booleans on complete assignments. There is no partial-assignment evaluator in this API.

| Node | Meaning |
| --- | --- |
| Distinct(channel, collection, cells) | Values at every two different positions are unequal. A `set` removes duplicate cells; a `list` retains occurrences. Empty and singleton collections are true. Canonical output expands this macro to inequality pairs. |
| Pair(channel, cells, table) | The ordered values at the two cells belong to the explicit allowed-pair table. Its axes use the board's actual numeric alphabet. Swapping cells transposes the table. A pair with the same cell on both axes uses only diagonal table entries. |
| Allowed(channel, cell, values) | The cell's value belongs to this explicit numeric set. An empty set is false. |
| SumEqual(channel, left, right) | Exact equality of sums over two occurrence lists, including repeated visits. Canonical equations cancel common occurrences, divide coefficients by their common factor and choose a fixed sign. |
| SumTotal(channel, cells, total) | The values read on the channel at the distinct cells add up to the integer total, using exact integers. Cells are a sorted set. Canonically an empty set holds only for total 0, a total outside n times the least or greatest alphabet symbol holds nowhere, and a single cell becomes Allowed on the alphabet symbol equal to the total. |
| CountAtLeast(D, cells, digit, count) | The number of matching digit occurrences is at least count. Cells are a sorted list retaining occurrence multiplicity. |
| All(children) | Conjunction; empty All is true. |
| Any(children) | Disjunction; empty Any is false. |
| Not(child) | Boolean complement of the complete child formula. |

`D` is the face digit. `V` is the effective value and equals D when nothing in the file can change or constrain that channel. A value modifier, liar cells, clue count, mapped values, an unrecognised header, or a definition that is not in the case file and whose meaning is not resolved can. A definition written in the case file itself (a `#` fragment or an HTTPS Markdown URL under `custom-rules`) does not, when its checked formula, with every shared term it reaches, never reads or binds V: no `V` or `effective`, no `valueAnswer` or `channelValue` read, no Channel-typed parameter or default of the definition itself (even one that defaults to D), no shared value answer of any name, and no literal "V". A call to a shared term whose Channel-typed arguments are all the literal "D" is judged by the callee with those parameters fixed to D: inside the callee a fixed parameter may only be passed on as a Channel argument of another such call, or compared with the literal "D" or "V" in an `if` (`=` or `!=`, either operand order), which then reads only the branch that applies; every other use, and every term the callee reaches, is judged by the same rule. Any other Channel argument (a parameter, a bound or let variable, "V", a computed value), a call with a missing or extra argument, and a Channel in any other position counts as touching V. The reading is taken from the checker's typed formula. A definition that does not check, reaches a shared term whose body is opaque, or names anything the check cannot resolve counts as touching V. The normaliser rewrites effective-value thermos, whispers, palindromes, renban and region sums, as well as parity-cell, pair, XV, Kropki and Marked Pairs restrictions from V to D only after establishing this identity. It does not construct effective-value tables for an unknown domain. General arithmetic, quantified witnesses, opaque custom terms and collections with computed selection have no lowering in this version; their declarations remain uncovered. Digits, counts and moduli in this finite fragment are safe integers. Whisper gaps accept finite numeric bounds; integral differences are compared to their exact ceiling or floor. The formula compiler's separate exact rational arithmetic remains unchanged.

## Coverage by declaration kind

`declarationRegistry` inventories all published kinds, including aliases. Its entries declare a lowering path or a specific unsupported reason. Tests compare the inventory with every rule page; adding, removing or renaming a kind requires updating the registry. Actual instance coverage also accounts for composition, parameters and expansion limits.

| Kind | Lowering |
| --- | --- |
| sudoku | Standard 9×9 composed houses; explicit board alphabet and givens retained. |
| unique, regions, extra-regions, disjoint-sets, irregular-regions | Set distinctness to all unordered inequality pairs. The five spellings share one lowering, so equal cell sets compare equivalent; a group already implied by a declared house reduces to nothing, as for any inequality pair. |
| clone | Equality table on every unordered cell pair. |
| diagonal | Distinctness on active coordinates satisfying row=column (main) or row+column=cols+1 (anti). |
| anti-knight | Inequality for every active (1,2)/(2,1) move edge. |
| anti-king | Inequality for every distinct active pair at Chebyshev distance one. |
| scoped-move | Explicit knight, king, orthogonal or bishop edges; bishop covers every diagonal distance, across inactive gaps. Forbid same or consecutive numeric digits when either endpoint is scoped. |
| relation-scope | Every selected pair of cells, taken in increasing row-major order, meets at least one listed relation, or with `negative` true none of them. A pair is selected when both cells are in `cells` (a set, so order and repeats do not matter), they differ, they are one `move` apart (orthogonal by default; `mode` "moves"), or any two cells when `mode` is "all", and for `mode` "incident" at least one of the two is an anchor. `except` pairs are undirected and drop out; an exception that repeats a cell names no pair, and one that is not two cells makes the declaration false. Positive scope is one ordered Pair table per selected pair holding the union of the relations, so the order and repeats of the relations do not matter. Negative scope is one Pair table per selected pair and relation, as for negative, so it shares that normal form. Directed relations such as `less` read the earlier cell first. The default `channel` D reads printed digits and is covered whatever the effective-value domain. Channel V is converted to D with the `value-channel` rewrite when the effective-value domain is resolved and left uncovered when it is not. A scope that expands past 1,000,000 value combinations leaves the declaration uncovered. |
| limited-digits | The marked cells hold at most `max` different printed digits. The cells are a set, so order and repeats do not matter, and only the whole part of `max` counts. A limit below 1 allows no digit, so no assignment holds; a limit of at least the number of cells or of alphabet digits asks nothing; a limit of 1 makes every pair of cells equal, the normal form of clone. Otherwise it is an exact disjunction over the subsets of that many alphabet digits, each leaving every cell Allowed only the digits of the subset; a smaller support sits inside a larger subset. A limit that needs more than 10,000 subsets, and a pair expansion past 1,000,000 value combinations, leave the declaration uncovered. Reads D only, so it is covered whatever the effective-value domain is. |
| look-and-say | Each listed digit occurs exactly the stated number of times among the marked cells, on printed digits. The cells are a set; the entries of `counts` are independent, so their order and repeats do not matter and two different counts for one digit cannot hold. Unlisted digits are free. Each entry is written as at least that many cells holding the digit and, below the number of cells, not one more; a count of zero is Not at least one, a count above the number of cells never holds, and a digit outside the alphabet is held by no cell, so only a count of zero is met. Reads D only, so it is covered whatever the effective-value domain is. |
| digit-profile | Printed digits only. Each listed class (a set of numbers; classes may overlap and are counted independently) holds its stated number of the listed cells, exactly or, with `comparison` "at-least", at least. The cells are counted as listed, so a cell written twice counts at each place and holds the class at both or neither. A class with no alphabet digit holds no cell, one with every alphabet digit holds all of them, and a single digit is an exact count (the look-and-say lowering). Otherwise the count is a disjunction over which places are the holders, each holder Allowed the class and, for an exact count, every other cell Allowed the rest of the alphabet. A class list and count list of different lengths, or a negative count, cannot hold. With `windowLength` the counts apply to every full window of that many cells, and `loop` adds the windows that wrap round; a longer window adds no condition and a length below 1 cannot hold. `exhaustive` allows each cell only digits of some class. `selfCount` makes every occurring digit occur as often as its value, written as for counting-circles. `repeats` false makes the listed digits differ, and a cell written twice then cannot hold. A profile that reads the effective-value channel, a `maximumDistinct` bound (Limited Digits lowers that on its own), `balancePairs`, `sumFree`, a count that is not a whole number, a class count needing more than 5,000 choices of holders and a profile needing more than 200,000 count terms stay uncovered. |
| allowed-digits | Membership at every path cell. Repeated visits do not multiply membership constraints. |
| absent-digits | No marked cell holds a listed digit, on printed digits: Allowed at every cell, restricted to the alphabet symbols that are not listed. Listed digits outside the alphabet exclude nothing, and the order and repetition of the listed digits do not matter; a list with no alphabet digit adds no restriction (an empty list is rejected when the case is read). Repeated cells count once. |
| parity-cells | Membership in the odd/even part of the actual alphabet when V=D; negative odd digits and zero retain their numeric parity. |
| pair | Exact table for difference, at-least, ratio, sum, less, multiple and shift over the actual alphabet. Keywords retain cell direction; swapping axes transposes the table. Arithmetic uses exact integers. The default `channel` V converts to D when the effective-value domain is resolved; `channel "D"` reads printed digits and is covered whatever the domain. |
| kropki | Single or grouped white (difference 1) and black (ratio 2) marks, including zero/zero for ratio. Selected allGiven kinds forbid their own relation on orthogonal edges outside their own mark list. |
| xv | Single or grouped X (sum 10) and V (sum 5) marks, with independent allGiven restrictions. |
| marked-pairs | Grouped X, V, white and black marks with independent allGiven restrictions. |
| quadruple | At-least counts of each listed digit over the cell set. Duplicate listed digits increase the required count. |
| outside | At-least counts over cell occurrences. Order is immaterial; repeated positions still count. |
| negative | Each listed relation is forbidden on orthogonal face-digit pairs in its direction and within scope, excluding exactly its declared exception pairs. |
| cage, killer | Untotalled cages lower to distinctness unless repeats is true. Killer is the cage alias. A supplied total (`total` or `sum`, an integer) adds SumTotal over the cage cells on the V channel, converted to D with the `value-channel` rewrite when the effective-value domain is resolved and left uncovered when it is not. Face digits differ unless repeats is true, with or without a total. With `channel` "D", the total is a SumTotal over the cage cells on the D channel directly, with no `value-channel` rewrite, so the declaration is covered whatever the effective-value domain is. An explicit `channel` "V" behaves as the default. A total that is not a safe integer leaves the whole declaration uncovered. |
| arrow | Shaft sum equals the bulb. A complete one-cell bulb is SumEqual on V between the shaft and the bulb cell, converted to D when the effective-value domain is resolved and left uncovered when it is not. A bulb of several cells is the decimal number of its printed digits in the supplied order, written as a D-channel SumEqual in which a bulb cell worth 10^k appears 10^k times (a cell at several positions adds its weights), with Allowed restricting each bulb cell to the alphabet symbols from 0 to 9; the restriction is trivial on alphabets inside 0..9. Each declaration is its own equation, so several shafts over one bulb stay separate. A partial arrow reads D throughout and holds when the bulb value minus the shaft sum is a sum of a nonempty list of alphabet symbols. On an alphabet of nonnegative integers it lowers to an Any over the bulb readings of the bulb-cell values (Allowed) together with the shaft totals that leave such a remainder (SumTotal). A shaft cell visited more than once counts at each visit: each of its alphabet values is a branch of its own (Allowed), and the cells visited once keep the plain total, so a shaft of only repeated cells needs the remainder to be exactly what the repeats leave. A partial arrow on any other alphabet and a bulb with decimal weights totalling over 1,000,000 occurrences leave the whole declaration uncovered. So does a partial arrow that crosses a cap: over 100,000 bulb readings, over 20,000 readings of the repeated shaft cells, over 2,000,000 pairs of a bulb reading and a reading of the repeated shaft cells (refused before any are enumerated), or over 100,000 surviving branches. The caps, not the length of the bulb, decide: a four-cell bulb lowers on a small alphabet with a short shaft and is refused on nine symbols with a long one. |
| diagonal-sum, little-killer | The listed cells, each counted once per occurrence, add up to the sum. Little Killer is the Diagonal Sum alias. The default `channel` D reads printed digits. Channel V is SumTotal on the V channel, converted to D with the `value-channel` rewrite when the effective-value domain is resolved and left uncovered when it is not. With `repeats` false the values on the ray must also differ in that channel, so a cell listed twice can never satisfy the ray. A ray that lists a cell more than once with repeats allowed is an exact disjunction over the alphabet values of its repeated cells, each leaving a SumTotal over the cells listed once; more than 20,000 such readings, or a sum that is not a safe integer, leave the declaration uncovered. |
| double-arrow | The values of the line cells, in the selected channel, add up to the sum of the two end values: a SumEqual with the line on one side and the ends on the other, so the order of the ends does not matter and a cell listed twice counts once per occurrence. The default `channel` D reads printed digits and is covered whatever the effective-value domain. Channel V is SumEqual (and Distinct) on V, converted to D with the `value-channel` rewrite when the effective-value domain is resolved and left uncovered when it is not. With `repeats` false the values of the ends and the line, taken together, must also differ (Distinct over those cells); the default `repeats` true adds no distinctness. Ends that are not two cells, a cell listed twice with `repeats` false, and a distinctness expansion past 1,000,000 value combinations leave the declaration uncovered. |
| equal-sums | Every group has the same total in the selected channel: each group after the first is a SumEqual against the first group. Each group is a set of cells, so a cell listed twice in one group counts once, and an empty group totals zero; one group alone, or no group, adds no equality. The default `channel` D reads printed digits and is covered whatever the effective-value domain. Channel V is SumEqual on the V channel, converted to D with the `value-channel` rewrite when the effective-value domain is resolved and left uncovered when it is not. With `repeats` false the values read in the selected channel must also differ within each group (Distinct in that channel, converted with the equations); the default `repeats` true adds no distinctness. A group needing over 1,000,000 finite value combinations for its distinctness leaves the declaration uncovered. |
| extremum, neighbour-extremum | Marked cells against their neighbours on printed digits: every marked cell is strictly below (`min`) or strictly above (`max`) each cell of its neighbour set, one ordered Pair per marked cell and neighbour. Extremum is the Neighbour Extremum alias, so both spellings share one lowering. The neighbour set is the explicit `neighbours` list when given (deduplicated, ignoring `neighbourhood` and `boundary`), else the active cells one `neighbourhood` move away (orthogonal by default; diagonal, king, knight and bishop use the published moveRelation, bishop across inactive gaps), without the marked cells when `boundary` is true (the default). A marked cell listed among its own neighbours is compared with itself and never holds. With `exhaustive` true each unmarked cell also needs, among the cells one move away (marked or not, whatever `boundary` and `neighbours` say), one that is strictly below it for `min` or above it for `max`: an Any of Pair tables per unmarked cell, false when the cell has no such neighbour. | equality-cage | Printed digits of the cage cells (a set; a cell listed twice is not lowered) are all different, none equals the middle value (|alphabet|+1)/2, and the number of low odd digits equals the number of high even digits while the number of low even digits equals the number of high odd digits. Low and high mean below and above the middle value, compared as a number, so an even alphabet forbids nothing; parity is numeric (negative odd digits are odd, zero is even). Lowered as Distinct on the cells and an exact disjunction, over every assignment of one of the four classes to each cell with balanced counts, of Allowed on each cell for its class; a class with no alphabet digit is never assigned. A cage of odd size cannot balance and is false. The declaration reads D only, so it is covered whatever the effective-value domain is. A cage whose class assignments pass 1,000,000 value combinations stays uncovered. |
| layered-cage | Printed digits of the marked cells (a set; a cell listed twice counts once). A digit is upper when it is in `upper`; digits listed outside the alphabet match nothing, and the order and repeats of the list do not matter. Cells in one row are all upper or all lower, and every row holding an upper cell lies above every row holding a lower one. Lowered as one Pair table for every two marked cells: in one row the layers are equal, and in different rows the cell in the lower row may not be upper unless the cell above is upper too. Reads D only, so it is covered whatever the effective-value domain is. A cage whose pair tables pass 1,000,000 value combinations stays uncovered. |
| aggregate-equation, product-cage, cage-pair | Two expressions over aggregates of printed digits are compared by `relation` (default: equal). Each side sums or multiplies its terms; a term is a whole-number coefficient times a sum, product or count of an operand's cells raised to a nonnegative power, where a power of zero leaves the coefficient and a count is the number of cells. An operand may slice its list with `start` and `length`; a slice outside the list, or a `repeats` false operand whose digits are not all different, makes the declaration false (Distinct over the list, so a cell listed twice differs from itself). Lowered by what the sides are. Equality between sums and constants is one linear equation: SumEqual when the constant cancels, SumTotal when every cell has one weight, and for unit weights of both signs an exact disjunction over the reachable sums. Another relation between constants and multiples of one sum is an exact disjunction over the related pairs of values, each branch fixing the sums with SumTotal. A coefficient times a product of distinct cells against a constant is an exact disjunction over the digit assignments with that product, or any cell holding zero when the product is zero. | magic-square | Each place is nine cells in row order; at least one place holds the printed digits 1 to 9 once each, with its three rows, three columns and two diagonals totalling 15. A declaration needing over 1,000,000 value combinations stays uncovered. |
| aggregate-groups | Every group, a list of cells in which a cell listed twice counts twice, has the same aggregate of printed digits; `operation` is sum (the default), count, mean or product. Count: true when every group has the same number of cells, false otherwise. Mean: cross multiplication, so an empty group places no condition; each other nonempty group is a SumEqual against the first one, with the first group's cells repeated once per cell of the other and the other's once per cell of the first. Product: lowered when every group has at most one cell (an empty group multiplies to one) or all groups list the same cells the same number of times. With `maximumShared` m, the `groups` (the left and right lists when absent; `multiset` plays no part) are compared pairwise: two groups share at most m distinct digits, repeated occurrences counting once, which is the negation, for every set of m+1 alphabet digits, of all of them being present in both groups; a bound of at least the alphabet size is always met. ## Custom definitions

An instance of a definition written in the case file (`custom-rules`) is lowered by reading the definition's checked formula with the instance's parameters bound. Everything that does not depend on a cell digit is computed exactly: positions, sizes, sets, intervals, local bindings, shared terms and quantifiers over finite collections. A cell digit `D(c)` stays symbolic as a sum of weighted cells with a constant, and each comparison of such sums becomes the finite primitive that states it. Two definitions that state the same condition, whatever their names, parameter names, parameter order or spelling, give the same normal form; a different comparison or constant gives a different one. The result joins the file's other constraints, so a custom definition whose formula matches a library rule's formula has that rule's normal form.

| Condition on cell digits | Lowering |
| --- | --- |
| One cell against any test | Allowed with the alphabet digits that pass |
| A sum of equal-signed cells against any test | SumTotal for each accepted total, as Any over the accepted totals, or Not over the rejected totals when those are fewer; one total gives a plain SumTotal |
| Two cells against any test, including functions such as absolute difference and remainder | Pair with the explicit table |
| An equation or inequation between three or more cells with mixed signs and no constant | SumEqual, with repeated cells for weights, under Not for inequation |
| A weighted sum of three or more positive cells equal to one total | The Little Killer repeated-cell lowering |
| A comparison of functions of cell digits that read at most two cells together | Pair or Allowed |
| The number of listed cells holding one digit, against any test | CountAtLeast bounds: each run of accepted counts is a lower bound and a negated upper bound, as Any over the runs, or Not over the rejected runs when those are fewer |
| And, or, not, implies, iff, conditional on conditions | All, Any, Not, with constants folded |

A definition stays uncovered, with the reason below naming what is missing, when it reads the effective value V, quantifies over a domain with no finite enumeration, chooses a shared witness (a subset, list or partition), reaches a shared term that calls itself, multiplies cell digits or otherwise leaves a linear form, relates three or more cells with no finite primitive (an inequality between weighted sums, or a weighted sum against a range), counts conditions that are not a single digit at a cell, or cells that hold different digits, reads a shared answer (a route, selection, shading, network or value map), uses a primitive with no finite lowering, exceeds 1,500,000 evaluation steps, 20,000 totals of a sum or 100,000 repeated occurrences, or is undefined for the supplied parameters. The reasons are exported as `customRefusals` and each begins with the matching text. A definition that did not pass the checker has no meaning to lower. A reference to a definition that is not in the file keeps its earlier reason.

## Composition and rewrites

Supported declarations validate parameters and active cells before composition. Parameter types and enum values are checked without coercion. Invalid parameters remain errors under negation or false conditions. Instance IDs are optional, including when a kind repeats. Each unlabelled declaration has a one-based `source.position` in document declaration order, across rules fences and counting labelled declarations too. This positional identity is stable for the same declaration order and separate from mathematical identity; it is never printed as a label. Identical repeated lines preserve their meaning and source spans; an explicit ID reused for a different declaration is rejected. An explicit `not` complements the complete base formula. Two prefixes cancel. `negate: all` adds one complement per base declaration before applying conditions.

`R if P` lowers to Any(Not(P), R); `R unless P` to Any(P, R), after base negation. `distinct` uses the primary collection's declared semantics, including repeated path positions. `connected` evaluates fixed orthogonal geometry. Conditions require a nonempty primary cell list. `uniform` awaits shared shading coverage.

Rewrites are terminating and versioned. Each record has its name, version, before/after primitive keys and originating sources:

| Rewrite | Justification |
| --- | --- |
| distinct-pairs | Pairwise inequality exactly defines distinctness. |
| pair-order | Cell sorting transposes the explicit table; table entries are sets. |
| boolean-canonical | Flatten associative All/Any; sort and deduplicate children; fold identities, constants, full/empty tables and membership sets; self-pairs read table diagonals; complement complete pair tables under Not; fold impossible multiplicity counts, divide repeated-cell weights by their common factor with the threshold rounded up, saturate weights at the threshold, and reduce singleton counts to membership. |
| double-not | Complementing twice preserves a complete Boolean meaning. |
| house-implied | Remove positive inequality already asserted by an unconditional house; retain the house and its proof link. |
| value-channel | V equals D in the absence of uncovered value bindings or of definitions that can read or bind V. |
| sum-equation | Cancel common sum occurrences, divide integral coefficients by their common factor, and orient the first nonzero coefficient positively. |
| fog-sets | Canonicalise initially lit cells and trigger sets, union lights for identical trigger sets, and remove links with inactive triggers without changing the presence of links. |

House removal works pair by pair: no single house needs to contain the entire marked group. Each comparison side derives its own baseline; differing houses stay visible as board differences. Conditional and negated declarations never become baseline houses. Removed pairs retain their rule source on the house link and rewrite record. Original primitive keys and their sources remain in the source map even after flattening or removal. Declaration order never enters mathematical identity.

Source maps use canonical primitive JSON as keys, and `house:<cell-set JSON>` for retained house witnesses. `board` links recognised board headers. Several declarations can map to one primitive. Reference checking and semantic reading share Markdown fence boundaries, so prose and nested examples remain outside declarations. Spans use the reader's UTF-16 offsets, one-based lines and Unicode code-point columns, with exclusive ends.

## Pair relations, multiplicities and negative scopes

`pair` uses its published keyword forms, such as `pair r1c1-r1c2 sum 10` or `pair r1c1-r1c2 less`. Numeric relation arguments must be safe whole numbers. Difference and at-least compare absolute differences. Ratio means either value multiplied by the argument equals the other, including zero. Multiple means the numeric maximum is an integer multiple of the numeric minimum when the minimum is nonzero; two zeros also satisfy it. Shift excludes 5 and requires exactly one of equal parity and equal membership in values greater than 5. No relation assumes digits 1–9.

Quadruple cell collections remove duplicate positions. Outside cell collections preserve occurrences, including repeated visits, while sorting their order. Both retain digit-list multiplicity; extra copies and unlisted digits are permitted. Canonical counts combine repeated occurrences into cell weights, divide weights by their greatest common divisor while rounding the count up, then cap each weight at the required count and repeat until stable. A count over one distinct cell becomes digit membership. Thus `outside r1c1-r1c1 digits [1,1]`, `outside r1c1 digits [1]` and `allowed-digits r1c1 digits [1]` share a canonical form. Negation complements the complete bundle of required counts.

Negative declarations require `relations` and `except`. Validated relation records are deduplicated by operator and value before pair expansion and resource accounting. Absent `within` covers all orthogonal edges; `within []` covers none. A nonempty scope covers an edge only when both endpoints belong to a common listed group. Direction restricts those edges to horizontal or vertical. Exception pairs are unordered sets of exactly two positions; lists and groups are validated against active cells. Asymmetric relations use row-major endpoint order before canonical pair transposition.

Exceptions belong to each negative declaration. A pair carrying a white clue does not exempt a black negative, and a V clue does not exempt an X negative. Separate declarations preserve independent exception lists. A declaration listing several relations explicitly shares its own exceptions across those relations. The API never infers exceptions from other declarations or drawings.

XV, Kropki and Marked Pairs lower their positive marks on V and each selected `allGiven` restriction as a separate Negative on D, exempting only the pairs of that kind in the same declaration. A single primary pair is appended to its chosen kind before lowering. Empty selected lists prohibit that relation on every active orthogonal edge. Negation complements the complete bundle. If effective values are unresolved, the whole declaration remains uncovered.

## Paths, windows and regions

Paths retain their ordered occurrences. Adjacency rules expand to their exact edges, so splitting or joining declarations compares equally when the resulting edges agree. Branches are supplied as separate paths; touching artwork adds no edge. Thermo direction starts at the bulb. Direction-free rules reverse through their lowered clauses. Palindrome, interval and window rules retain their whole scope; splitting them does not generally preserve meaning.

An explicit `edges` list on whispers, whisper, close-whispers, parity, primality and shifter-line lowers to the kind's pair test on exactly those edges. The list must name two different active cells per edge and form one connected network; edges are unordered and deduplicated, so splitting the same edges across declarations, repeating an edge or reversing it compares equally, while a different or additional edge compares as different. A supplied `line` must lie on the network. Primality and shifter-line also apply their per-cell restrictions to every cell on the network. A closed network, an empty list, an edge joining a cell to itself, a disconnected list, or a condition on a network leaves the whole declaration uncovered. Modular, entropic and summit read every simple traversal through a junction, not a single edge, and renban, nabner, bremban, region-sum, thermo and slow-thermo read whole sets, orderings or segments; their `edges` stay uncovered.

Loop closure follows the published shared predicates: only paths longer than two add a last-to-first edge. Cyclic three-position windows require at least three positions. A closed two-position modular or entropic path has no windows; its open counterpart has the explicit two-position class restriction. Repeated closing endpoints remain occurrences, rather than being removed. A cyclic window can therefore differ from an open path with its first position repeated at the end. An open path repeating its first two positions captures all cyclic triples.

Entropic classes use the ordered alphabet, whose size must be divisible by three. Modular remainders are normalised even for negative digits. ## Fog play state

A `fog` header lowers to `{op: "Fog", initiallyLit, links?}` in `play` and a `header:fog` coverage entry. Initial cells, trigger cells and lit cells are sets. Links with the same canonical trigger set have their lights unioned. Cell coordinates and zero-based row-major indices identify spots; initial light and link lights must identify active cells. Missing `initiallyLit` defaults to empty. Missing links select neighbourhood reveal; present empty links select links-only reveal. These remain distinct canonical forms.

Trigger coordinates may be off the board or identify inactive cells. Those spots are never correct, and links containing them are removed from canonical play. Empty trigger sets, malformed links and unknown fields are rejected.

`visibleCells(form, entries, answer?)` returns the cells visible under the current entries. A link fires only when all its triggers have correct entries. Revealed light never fires another link by itself. Without links, a correctly entered non-given reveals its active 3×3 neighbourhood; a given typed over correctly reveals itself alone. Initial light always remains. Erasing or changing an entry retracts the light it supplied. Answer availability and coverage are separate: omitting `answer` means no answer is available, so any placed digit counts subject to the cell’s given value. Supplying an answer, including `{}`, means an answer is available; only covered cells whose entries match it count. Given values must agree in both modes. The function computes play state without evaluating solution constraints.

Play differences appear separately as `Play` differences with header provenance. Equal covered fog forms can establish whole-file equivalence; any uncovered declaration still makes the comparison unresolved.

## Input bounds and verification

The finite fragment accepts 1–64 distinct safe-integer alphabet digits and 1–1024 active cells. A declaration can expand at most 1,000,000 value combinations; a file at most 2,000,000. File accounting folds identities and deduplicates canonical clauses before charging expansion. Crossing an expansion bound reports the declaration as uncovered. It never establishes equivalence by truncation.

The synthetic tests cover every registry entry, line permutations, duplicated clauses, source merging, idempotence, each rewrite's satisfying cases and near-misses, and exhaustive small assignment checks under house premises. They also cover whole-rule negation, condition scope, nonstandard boards, mixed coverage and retained rational comparison.
